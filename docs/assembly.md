# M1 实验组装与首次上电

状态：**基础光驱查询已实测，完整验收仍开放**。2026-10-31 已完成固件烧录、UART0、Hub/光驱 Full-Speed 枚举和 61.2 秒连续 13 次介质就绪；首次失败条件见 [首次上板记录](records/2026-10-31-m1-first-boot.md)，后续见 [空 Hub 记录](records/2026-10-31-m1-empty-hub.md) 和 [光驱实测记录](records/2026-10-31-m1-optical-probe.md)。下面是信号和电源拓扑，供电隔离与带载能力仍未独立验收。

## 本轮需要什么

用户已确认拥有 ESP32-S3、UJ-898、Type-C Hub 和电源。组装前核对：

| 项目 | 作用 / 是否需要补充 |
| --- | --- |
| SATA / Slimline SATA → USB 光驱桥接器 | UJ-898 不能直接接 USB 或 GPIO；需确认已有桥接器适配光驱接口并支持 ATAPI，而不是只有硬盘功能 |
| 独立 UART0 调试路径 | 开发板若有板载 USB-UART 口可直接用；若只有原生 USB 口，需要 3.3V 逻辑的 USB-UART 转接器和连接线 |
| USB Host 转接/供电接口 | 必须有正确角色与 VBUS 供电路径；可能需要适配具体开发板的 OTG 转接或有供电隔离的 USB 接口板，型号确认后再决定 |
| 万用表 | 建议用于上电前通断检查及 5V 稳态测量；不能据此排除瞬态跌落 |
| 示波器 / USB 电压电流表 | 出现重启、读盘失速或供电疑点时再用；电流表需支持数据透传，且插入后可能引入压降 |
| 真正 Audio CD | M0 提取音轨及后续 M2 所需；无盘也能进行初步 INQUIRY / sense 验证 |

M1 无需 DAC、功放、扬声器或 SD 卡。空白 CD-R/RW 只为后续刻录能力查询准备，不影响本轮只读探测。

## 先确认两个独立通道

```text
电脑 ── USB ── 板载 USB-UART / 外接 USB-UART ── UART0 ── ESP32-S3
                                                           │
                                          原生 USB OTG D−/D+
                                                           │
                                         Host 接口 / 可选供电 Hub
                                                           │
                                             SATA-USB 桥接器
                                                           │
                                                        UJ-898
```

电脑通过 UART0 记录日志；ESP32-S3 通过原生 USB 控制光驱。电脑不能同时作为同一条 USB 数据链路的第二个 Host。

ESP32-S3 原生 USB 通常为 GPIO19（D−）、GPIO20（D+）；默认 UART0 为 GPIO43（TX）、GPIO44（RX）。**必须以具体开发板原理图和丝印为准**，确认这些针脚未接其它功能。优先使用板载 USB 差分布线，不用长杜邦线替代 USB 线。

外接 USB-UART 的信号连接：

| USB-UART | ESP32-S3 |
| --- | --- |
| RXD（3.3V 逻辑） | UART0 TX，默认 GPIO43 |
| TXD（3.3V 逻辑） | UART0 RX，默认 GPIO44 |
| GND | GND |
| VCC / 5V / 3V3 | 默认不接；开发板从已确认的电源路径供电 |

串口为 **115200 8N1**。部分转接器的电源跳帽不控制 TXD 电平，需要查看转接器说明，不能只看 VCC 标签。

## Type-C Hub 的使用条件

- Hub 的上行数据口接 **ESP32-S3 Host**，光驱桥接器接下行 USB 口。PD 口通常仅用于供电，不作为 ESP32-S3 的数据入口。
- PD 供电不会自动把 ESP32-S3 的 Type-C 设备口变成 Host。Type-C CC 电阻、线材方向、接口板角色和 VBUS 路径需一起核对。
- 固件启用外部和多级 Hub，但 ESP32-S3 仍只运行 USB Full-Speed；Hub 不能提升它的上行带宽。兼容性必须以实际枚举和 BOT 返回值确认。
- 单口原生 USB 开发板若缺乏正确的 Host/Type-C 角色配置，不能仅靠换一根 C-C 线解决。先核对板、Hub 型号，再确定转接方式。
- 若 Hub 无法枚举，保留日志，再尝试有明确独立供电路径的桥接器直连，以区分 Hub 与桥接器问题。

对没有独立供电口的 Hub，应先确认上行 VBUS 的实际供电来源。光驱能吸盘只能说明机械部分得到供电；采用分叉 USB 辅助供电线时，还需核对 VBUS 是否隔离或回送，不能仅凭照片推断 Hub 有电或没电。模块上的 `S3-N16R8` 等标识不等于开发板型号；若背面有 `OTG` / `IN-OUT` 等焊盘，须查对应电路后再决定，不能按名称直接短接。

用户提供的 [ESP32-S3-COREBOARD V1.4 原理图](../hardware/ESP32-S3-N16R8/ESP32-S3-SCH-V1.4.pdf) 中，`USB-OTG` 0 Ω 支路与 USB2 的 D2 并联，作用是连接 USB2 VBUS 与板上 5V；它不是 GPIO3 接地配置。目录 README 对这一处的文字摘录与 PDF 不一致，以实际原理图连线为准。`IN-OUT` 则旁路排针 5Vin 的 D3，是不同的支路。上述结论属于图纸核对；实物焊装、载流能力和 Hub 兼容性仍需验证，详细测量及建议操作顺序见 [首次上板记录](records/2026-10-31-m1-first-boot.md)。

## 电源路径

光驱与主控可共享足额电源的不同支路，但光驱电机电流不能经过 GPIO、3.3V 稳压器或未经确认的开发板 USB 供电路径。USB 数据链路必须保持公共信号地。

1. 断电核对电源极性、光驱铭牌、桥接器要求、开发板供电入口以及 Hub 的 PD/上行/下行端口。
2. 明确整条链路的 VBUS 来源，确认供电 Hub 不会把电压回灌到不允许受电的板端或电脑端；多路 5V 不直接并接。
3. 确认光驱/桥接器得到规定的 5V 供电。固件不配置外部供电开关 GPIO、不协商 USB-PD，也不会凭空产生 VBUS。
4. 初次先不接光驱，确认主控 UART0 启动稳定，再连接确认后的光驱数据和供电路径。
5. 后续观察上电、吸盘、旋转过程的电压、重启与串口异常。若出现 brownout 或反复重枚举，先查电源和线材。

电源电流额定值按光驱/桥接器规格和测量确定；目前没有本项目的峰值电流数据，不给出已验证的固定安培数。

## 构建、烧录和恢复

先按 [固件说明](../firmware/README.md) 构建。烧录时只选择属于 Discora 的串口；其它项目设备不参与本轮操作。

优先通过板载 USB-UART 或外接 UART0 烧录。只有原生 USB 时，可先断开 Host 链路，通过手动下载模式烧录；应用切到 Host 后原生 USB 串口消失是预期行为，运行日志仍须从 UART0 获取。

外接 UART 且没有自动下载电路时，按住 BOOT（GPIO0），按一下 EN/RESET，再松开 BOOT 进入下载模式；具体按键和电路以板卡说明为准。不要修改 eFuse。

在 `firmware/` 中，用实际串口替换占位符：

```bash
idf.py -p <DISCORA_UART_PORT> flash monitor
```

先确认启动日志中出现 `Discora M2 TOC read-only probe` 和 `Waiting for USB optical drive`，再接入光驱。日志字段和测试矩阵见 [验证手册](validation.md#m1esp32-s3--usb-host)。本文没有预先填好的设备成功日志。

## 首轮验收顺序

1. 主控空载启动，UART0 持续可用，无重启。
2. 无盘连接光驱，记录 VID:PID、接口、端点、INQUIRY 型号和固件；合法“无介质” sense 是有效观察。
3. 插入 Audio CD，观察就绪状态。`medium ready` 只代表 TUR 成功；随后 `TOC validated` 输出曲目目录。两者均不代表 PCM 音频读取或播放通过。
4. 拔下和重连光驱，观察 device handle 关闭及重新识别。
5. 冷启动、重复插拔和异常路径按验证手册记录，再决定是否进入 M2。

型号未知或供电路径不明确时，先补充板卡、Hub、桥接器型号再落实物理接线；这不阻碍固件编码和离线构建。
