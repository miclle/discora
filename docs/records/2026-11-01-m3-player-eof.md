# 新播放器整轨与 EOF 实验

## 范围与设备

2026-11-01，0.6.1-player-eof，ESP-IDF v5.4 (`67c1de1eeb`)。ESP32-S3 N16R8 / UJ-898 HC10 / 桥接 `13fd:0840`，Full-Speed BOT `08/02/50`，IN81/OUT02、MPS64、LUN0；同张 13 轨 CD-DA，lead-out 252645。COM 身份为 `1a86:55d3` / `5CF9109063`。OTG 直连和辅助供电保持不动，无 Hub、无 DAC。

软件时钟以 176400 bytes/s 消费真实 CD 数据；验证生产与消费两端独立摘要、轨尾短块、EOF 停止与不再派发读取。RTS 复位启动，不是冷启动。未保存 PCM；整轨没有独立电脑完整参考。

## 软件检查

五组 ASan/UBSan 主机测试通过。将播放器 EOF fixture 改为 17 扇区，检查最后 1176 字节输出块（原 18 扇区只能覆盖短 READ 批次，输出块恰好整除），检查 EOF 无额外请求及显式重新播放。默认/软件时钟两配置均执行 set-target esp32s3 与 build。

## 原始证据

本地 `.local/bench/2026-11-01-m3-player-eof/`：实验/默认配置与构建日志、应用镜像、源快照、`direct.log`、`player-checks.json`、恢复日志及备份来源。不提交原始音频或构建输出。烧录前核对唯一 COM 身份及当前 0.4.3 应用，复用此前 `0x0..0x110000` 备份；只改写应用 `0x10000`，并保留 bootloader / 分区表。

## 实测结果

首轨 `[0,19373)`：生产和消费均为 45565296 字节、2422 次 READ CD；两端 SHA-256 均为 `73ad449e02aa5513ffb632bfd632a2bf6bc048dabb675b4ba958b26e9a54a38f`，与此前 MCU 首轨结果一致。最后输出块 1176 字节，EOF `match=1`，随后 stopped / queued=0 / next_lba=19373；后续两次状态采样 reads 保持 2422，没有越轨或追加读取。

本窗口零欠载、零读取错误、零离线。真实数据进入播放器后按软件时钟消费，约 258.307 秒音频；不涉及 I²S 或 DAC。

最后恢复默认关闭实验的 0.4.3，25.201 秒独立采集取得有效目录，无 READ CD、离线或传输错误；串口已释放。实验及恢复摘要保存在本地 `sha256.json`。
