# 2026-10-31：M2 音乐 CD 曲目目录实测

结论：**READ TOC 在本次 UJ-898 / HC10 + `13fd:0840` 组合上 bench-tested**。用户确认介质为音乐 CD；取得 13 条音频轨、0 条数据轨和 lead-out LBA 252645。尚未实施 READ CD、参考 PCM 对比或 I²S，M2 未整体完成。

## 硬件与操作

- ESP32-S3 rev v0.2，芯片已报告 16 MB Flash / 8 MB PSRAM；精确开发板版本未确认。
- 仅匹配此前确认的 Discora USB Single Serial（`1A86:55D3`）并核对序列号后操作；其它项目串口未打开、复位或烧录。
- UGREEN 无独立电源 Hub：`05e3:0610`、Full-Speed；USB 桥接器：`13fd:0840`、Full-Speed、class/subclass/protocol `08/02/50`、IN `81` / OUT `02`、MPS 64、LUN 0。
- INQUIRY：`MATSHITA` / `DVD-R   UJ-898` / `HC10`，PDT 05、qualifier 0。
- 原连接保持：COM 接电脑，native USB 经已桥接 USB-OTG 的板卡连接 Hub；Y 线主头接 Hub，辅助头接已开启的充电宝。按用户要求暂缓 Y 线内部隔离测量；隔离、负载电压/电流仍未验证，不从本次查询成功推断电源路径安全或长期能力。
- CD 标签、版本和压盘编号未提供；以本次 TOC 元数据识别实验介质，不推断专辑或曲名。
- 烧录后在同一 COM 以 RTS 复位并采集 125 秒；不是断电冷启动验收。未要求拔插或换盘。

## 真实响应和目录

两次 READ TOC 都使用格式 0、MSF=0，ATAPI CDB 补齐 12 字节。先请求 4 字节，返回头 `00 72 01 0d`；长度 `0x0072 + 2 = 116`，与 13 条轨道加一个 lead-out 一致。完整响应请求和收到均为 116 字节。两条命令均 CSW=0、residue=0、耗时 7 ms，两个响应头一致。完整目录通过序号、ADR、长度及 LBA 校验。

真实 UART 摘录：

```text
I (1435) usb_probe: command=READ TOC CSW=0 received=4 residue=0 elapsed_ms=7
I (1445) usb_probe: TOC header first=1 last=13 total_bytes=116
I (1455) usb_probe: command=READ TOC CSW=0 received=116 residue=0 elapsed_ms=7
I (1505) usb_probe: TOC validated first=1 last=13 tracks=13 audio=13 data=0 lead_out_lba=252645
I (1655) usb_probe: TOC metadata only; PCM audio not read
```

以下均为设备目录给出的 INDEX 01 起点及相邻区间。末 LBA 为排他边界；时长为 `MM:SS:FF`，每秒 75 帧，可能含轨间间隙，不等同于已经提取或听取的音频时长。所有曲目 CONTROL=02，音频/数据位未置位；尚未据此验证声道或音频质量。

## 连续观察结果

- 125 秒采集内只出现一次 ESP 启动；TUR 从启动后 1425 ms 到 124055 ms 连续 25 次成功，首尾跨度 122.630 秒，失败 0 次。
- Hub 和光驱各枚举一次，无光驱离线、BOT transport error、panic 或 brownout。Hub 的 `device closed` 是本探测 client 释放 Hub handle，底层 Hub 服务继续处理光驱。
- 一次成功目录读取后只轮询就绪，不在同一窗口反复读取 TOC；本次不是换盘、重复插拔、故障恢复或长时间播放测试。
