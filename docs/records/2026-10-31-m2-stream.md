# 2026-10-31：长时读取、寻道和缓冲实验

本轮实现完整音轨、12 位置寻道及软件时钟缓冲实验；所有实验默认关闭、每次 MCU 启动最多一次。首两轮已出现真实故障，保留原始日志。顺序缓冲完成 600 秒，生产/消费及电脑独立参考的整段摘要一致，零欠载；寻道及完整首轨回读未通过。

## 硬件、环境和证据边界

- ESP32-S3 rev v0.2，器件报告 16 MB Flash / 8 MB PSRAM；精确开发板版本未确认。只按 VID:PID、序列号核对并操作 Discora COM；不打开其它项目串口。
- UGREEN Hub `05e3:0610`，桥接器 `13fd:0840`，Full-Speed，class/subclass/protocol `08/02/50`，IN `81` / OUT `02`，MPS 64，LUN 0；MATSHITA UJ-898 / HC10。
- 同一 13 轨音乐 CD，lead-out LBA 252645。短探测的轨 1、LBA 150 / 8 扇区继续与此前电脑参考 SHA-256 相同。
- 连接延续前轮：COM 接电脑，native USB 接 Hub，光驱数据头接 Hub、辅助供电接充电宝。此次未要求用户插拔；未在读盘时测量电源，不能由症状判定电源正常或故障。Y 线隔离仍未验证。
- ESP-IDF v5.4 (`67c1de1eeb`)，Xtensa GCC 14.2.0；UART0 115200，main stack 8192。USB 接收及 PCM 环形缓冲均使用内部 RAM，不用 PSRAM DMA。
- 三轮是独立烧录/RTS 启动后的窗口，不拼成连续运行时长，也不计作真实断电冷启动验收。
- 原始日志、源码、sdkconfig、产物与回退备份存于 Git 忽略的 `.local/bench/2026-10-31-m2-stream/`，与构建清理目录分离。不保存或提交音乐 PCM。

## 离线检查

`python3 firmware/tests/run_host_tests.py` 通过：原协议 fixtures / 10,000 组输入，加上 20,000 次环形队列写读、独立递增帧顺序、回绕、满空拒绝、帧对齐及跨轨游标边界。开启 ASan/UBSan。合成 fixtures 不是光驱响应或播放结果。

默认关闭和本轮实验配置分别执行 `idf.py set-target esp32s3 && idf.py build`；构建结果及校验值在下方快照中记录。[ADR-0005](../decisions/0005-stream-and-buffer-bench.md) 说明每阶段、内存所有权和软件时钟模型。

## 第一轮：0.4.0，寻道失败

短探测成功，256 扇区短突发为 725783 bytes/s。之后：

```text
I (8741) cdda_bench: seek step=1/12 track=1 lba=150 sectors=8 elapsed_us=3797676 repeat=match
W (18421) usb_probe: USB status=4 ep=0x81 actual=0
I (18431) usb_probe: command=REQUEST SENSE tag=43 requested=18 LUN=0
E (21451) usb_probe: command=REQUEST SENSE transport error=ESP_ERR_TIMEOUT elapsed_ms=3020
W (21461) usb_probe: BOT recovery=ESP_OK; command probing stopped until reconnect
E (21481) cdda_bench: read failed track=13 lba=223917 sectors=8
I (21481) cdda_bench: extended bench failed (software sink only; not I2S playback)
```

- 12 个位置只完成第 1 个，轨 1、LBA 150 两次摘要一致，首次定位耗时 3.798 秒。
- 第 2 个位置是轨 13、LBA 223917，Data-In STALL 后 REQUEST SENSE 触及 3 秒截止。随后光驱离线重枚举；完整首轨与缓冲阶段未运行。
- 首版安静日志也隐藏了失败 READ CD 的 CSW 行；不补造原始 CSW。后续改为只隐藏成功行，失败状态始终记录。
- 主机采集 31.559 秒，单次 ESP 启动，光驱两次枚举；没有继续自动触发音频实验。

## 第二轮：0.4.1，完整首轨读取失败

单独关闭远距离寻道，短探测成功，256 扇区短突发 687477 bytes/s。尝试从完整首轨 INDEX 01 / LBA 0 开始：

```text
I (4811) cdda_bench: extended bench profile seeks=not_run paced_seconds=600
I (4811) cdda_bench: full-track start track=1 lba=0 sectors=19373
E (6711) usb_probe: command=READ CD transport error=ESP_FAIL elapsed_ms=1886
W (6731) usb_probe: CDDA failed track=1 lba=0 sectors=8 result=2
I (6741) cdda_bench: full-track failed track=1 bytes=0 commands=0 elapsed_us=1928868 bytes_per_sec=0 longest_read_us=0
I (6751) cdda_bench: extended bench failed seeks=not_run (software sink only; not I2S playback)
```

首个完整轨请求在 Data-In 收到 USB status=1、actual=0，EP0 恢复失败，光驱自动离线重枚举。完整轨收到的有效字节为 0；缓冲阶段未执行。主机采集 16.853 秒，单次 ESP 启动，光驱两次枚举。

这两轮表明短顺序区间可读，而改变位置后的读取失败；不能据此独断为介质、机械、电源、Hub、Full-Speed 或固件中的某一项原因。

## 第三轮：0.4.2，仅顺序衔接缓冲

明确关闭寻道和完整首轨两个阶段，日志应为 `seeks=not_run full_track=not_run`。从短探测末尾 LBA 414 接续，避免回跳到失败位置；目标是 600 秒 / 45000 扇区，不循环较短片段。单条命令仍不跨轨，目录连续时拆分后接下一轨。

缓冲容量 150528 字节（64 扇区，约 0.853 秒），预填 112896 字节（48 扇区，0.64 秒）后启动独立软件时钟任务，按实际单调时钟 176400 bytes/s 消费。两端分别 SHA-256，结束需字节数一致、摘要一致、零欠载、消费任务已结束。此处没有 DAC、I²S 或可听播放反馈。

## 电脑独立参考和失败位置对照

用户完全断开 Hub、等待 5 秒后改接电脑及光驱，`drutil list` 核对 UJ-898 / HC10。桥接器在电脑为 High-Speed 480 Mb/s；它与 MCU 的 Full-Speed、命令实现及供电路径不同。

通过 Audio CD 文件系统读取 AIFF-C `sowt` 数据，核对 2ch / 16-bit / 44.1 kHz；仅在内存中分块 SHA-256，不保存音乐转储。请求 `F_NOCACHE` 成功，但该路径仍不是直接 SCSI trace，也不排除光驱/桥接器自身缓存。

| PC 参考 | 实测 |
| --- | --- |
| LBA 0 / 8 扇区 | 18816 字节，399 ms，SHA-256 `c858b21ce4b78945461aee9c8afc83c58d75f20f0971d70b4407538abb3f8af6` |
| 轨 1、LBA 150 / 8 扇区 | 18816 字节，66 ms，摘要与既有参考相同 |
| 完整顺序窗口 | LBA 414–45414，105840000 字节，53032 ms，完整 SHA-256 与 MCU 生产端 / 消费端全部一致 |
| 轨 13、相对 150 / 绝对 LBA 223917 | 18816 字节，331 ms，SHA-256 `d638921c166885d310b28e6f9457c706d7c20f6d95299df64d865f3f7af90e91` |

完整 PC 参考由轨 1 相对 414 起的 18959 扇区、轨 2 的 16088 扇区、轨 3 的前 9953 扇区拼接，与 MCU 区间相同。三方完整 SHA-256 为 `ab78109b2d48ad667ce5dbe0b75412cc1ebb546e2a15f0b64b6e41b1120f6f17`。

这证明本次长区间内容和缓冲顺序正确，并确认两个失败位置在电脑路径可读；不能据此单独归因于 Hub、电源、Full-Speed、固件或某个指令参数。MCU 随机/回跳读取仍未通过，不反复复位冲击同一失败位置。
