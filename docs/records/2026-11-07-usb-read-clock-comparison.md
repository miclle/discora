使用已有播放器的 `software-clock-no-I2S` 消费模式，按约 176400 字节／秒消费并丢弃队列数据，保留相同 READ CD 生产路径、2 MiB PSRAM 队列、3 秒预填、自动重缓冲及 USB 诊断。没有新增固件算法或恢复策略，不保存 CD PCM。本轮不启用逐轨摘要计算，因此不将读取完成计数表述为音频数据与电脑摘要一致。

### 4 次完成事件队列溢出的解释

`eof_trace` 显示第 1 轨 generation=3，最后 PCM 写入至 drain_start 的溢出数均为 0，约 57.710 ms 后 before_close/closed 为 2；第 2 轨 generation=4 对应从 2 增至 4，排空约 57.734 ms。两个窗口各增加 5 个 DMA 完成计数，后续正常供数和最终主动 stop 未新增溢出。

代码核对：`audio_i2s_eof()` 在 EOF 后设置 50 ms 排空期限，输出任务期间不再调用 I²S write；本机 ESP-IDF v5.4 的 TX DMA 回调在内部完成消息队列满时调用 `on_send_q_ovf`，适配器只累加此计数。结合时间戳，本次 4 次计数定位在 EOF 等待排空阶段，**不是 PCM 环形缓冲欠载，也不是 USB 断开**。不能将完成事件计数直接换算成丢音字节；DMA 回调也可能覆盖自动清零的静音。轨尾无缝／精确物理输出仍需独立验收，本轮不为了清零诊断计数而修改播放行为。

最终累计 PCM 提交 106073436 字节、DMA 完成 60131 次、补零计数 0；这些是软件提交与驱动事件证据，不能当作每一个样本均被喇叭完整重放的独立测量。
