# 2026-10-31：M2 READ CD 小片段、电脑对照和短突发

结论：**本组合的 READ CD 小片段和短突发已 bench-tested**。单/8 扇区与电脑端同盘同位置 SHA-256 一致，连续 256 扇区为 739,858 bytes/s。首次失败、两次超时、Hub 重新上电和主机路径差异均保留，不宣布完整 M2、电源或长时播放验收通过。

## 设备与环境

- ESP32-S3 rev v0.2，器件报告 16 MB Flash / 8 MB PSRAM；精确开发板版本未确认。仅按 VID:PID + 序列号核对 Discora COM，未打开、复位或烧录其它项目串口。
- UGREEN Hub `05e3:0610`，电脑还枚举 SuperSpeed Hub `05e3:0625`。SATA-USB 桥接器 `13fd:0840`，class/subclass/protocol `08/02/50`，UJ-898 / HC10，LUN 0。
- MCU 路径为 Full-Speed 12 Mb/s，电脑桥接器路径为 High-Speed 480 Mb/s；不能将后者当作前者的验收。
- 同一音乐 CD、Y 线和充电宝辅助供电。用户确认初始失败期间没有拔插、移动或开关供电。Y 线内部隔离及负载电压/电流仍未验证。
- ESP-IDF v5.4 (`67c1de1eeb`)，Xtensa GCC 14.2.0，UART0 115200，main stack 8192，USB DMA 不依赖 PSRAM。

## 首次失败：0.3.0-cdda-probe

先备份并核对已在板上的 TOC 固件，再烧录首个 READ CD 版本。TOC 通过后，只请求轨 1、LBA 150、1 扇区 / 2352 字节。

| 启动后发送时间 | 结果 | 后续 |
| --- | --- | --- |
| 1677 ms | 2073 ms 后 USB status=1、actual=0，ESP_FAIL | EP0 恢复失败，光驱离线并重枚举 |
| 30917 ms | 3025 ms 后触及 3 秒截止 | halt/flush、一次恢复，随后重枚举 |
| 56017 ms | 3025 ms 后触及 3 秒截止 | 一次 BOT Reset Recovery 为 ESP_OK，停止探测 |

三条 READ CD 均无成功 CSW，未得到有效音频。只有一次 ESP 启动，无 panic / brownout；光驱共枚举三次。采集原计划 125 秒，发现自动重枚举会再次触发实验后主动中断，最后设备时间 59057 ms，不能报告为完整 125 秒窗口。随后回退到 `0.2.0-toc-probe`，写入校验成功。

首版重连/TUR 状态变化会清除音频尝试标志。`0.3.1` 修正为每次 MCU 启动最多一次，重连不重新触发，默认关闭。音频 Data-In 截止改为 30 秒，普通查询/CBW/CSW/控制传输仍为 3 秒；[ADR-0004](../decisions/0004-bounded-cdda-probe.md)。

## 电脑参考

用户将 Hub 改接电脑，起初未枚举 Hub/光驱。`system_profiler SPUSBDataType` 没有返回有效设备清单，以 IORegistry 和 drutil 为准。Hub 所有线拔下、等待 5 秒后只接电脑，空 Hub 正常枚举；接回光驱后识别 UJ-898 / HC10 和 High-Speed 桥接器。

- `drutil list` 确认仅一台该光驱后，对 drive 1 执行 TOC。13 轨均为 2ch audio、no pre-emphasis、digital copy permitted。MSF 转 LBA 减去 150 帧后，全部轨道起点和 lead-out 与 ESP 目录一致；lead-out LBA 252645。
- 同次 `drutil status` 曾返回 No Media Inserted，但目录及随后挂载的 Audio CD 文件系统可读；保留不一致，不据该 status 行断言无盘。
- 电脑挂载 13 条音轨，首轨 AIFF-C 为 `sowt`、2ch / 16-bit / 44.1 kHz、11,391,324 PCM 帧，等于 19373 扇区 × 588。
- Python `aifc` 首先报告不支持该 compression，属于解析器限制；随后直接解析 COMM / SSND 元数据，在内存中读取轨内第 150 扇区起的 8 扇区。取得 18816 字节，非零字节 18568，含首次打开/寻道耗时 3857 ms。
- 没有保存 PCM 转储，只保留元数据和摘要。移动 USB 前释放光盘文件系统，没有退盘。

## 修正版本：0.3.1-cdda-probe，显式开启实验

默认关闭与显式开启配置均完成 `idf.py set-target esp32s3 && idf.py build`。主机协议测试通过 ASan/UBSan 和 10,000 组边界输入。用户完全断开 Hub 的线、等待 5 秒后接回 ESP32-S3、光驱及辅助供电；MCU 已启动等待设备，这不是断电冷启动验收。

准备期间记录有效 sense `06/29/00`、`02/04/01`、`06/28/00`，随后就绪并读到同一 13 轨目录。真实日志：

```text

I (45747) usb_probe: CDDA single-sector SHA256=0ecff6f2167d0c1262d8def6832262ed27c445497d00c3a713ba282e5280963e
I (45807) usb_probe: CDDA eight-sector SHA256=077f4fd78614582d1ef63501e42329222724ffe230882aa765f561f51bf2ee80
I (46637) usb_probe: CDDA burst complete start_lba=158 end_lba=414 batches=32 sectors=256 bytes=602112 nonzero_bytes=594100 elapsed_us=813821 bytes_per_sec=739858 longest_read_us=29290

```

固件内单扇区与批量前缀一致、两次 8 扇区一致；另外在电脑端核对，单/8 扇区 SHA-256 都与上述参考完全一致。该样本与 macOS `sowt` 小端音频 bytes 一致；不是 I²S 通道/时钟或其它 LBA 的读取偏移验收。

| 指标 | 结果与边界 |
| --- | --- |
| READ CD | 35 条均 CSW=0、精确长度、residue=0，传输错误 0 |
| 请求总扇区 | 273，含重复区间；唯一覆盖 264 扇区，LBA 150–414（排他） |
| 首次单扇区 | 3633 ms，超过旧 3 秒截止 |
| 连续短突发 | 32 批、256 扇区 / 602112 字节，覆盖 3.413 秒音频 |
| 短突发速率 | 813821 μs 内完成，739858 bytes/s，约为 CD-DA 1× 的 4.19 倍，包含日志开销 |
| 最长一次突发读取 | 29290 μs；含本次调用日志，不含此前 3.633 秒首读 |
| 窗口 | 主机 111.762 秒，单次 ESP 启动，Hub / 光驱各枚举一次 |
| TUR | 准备阶段 3 次失败且 sense 有效，随后 13 次成功 |
| 其它 | 无光驱离线、panic、brownout 或额外 ESP 启动；不是长时播放通过 |

不能把成功单独归因于 30 秒截止：本轮同时重新上电 Hub，并经过电脑初始化。首次约 2 秒的 USB 错误发生在旧截止之前，根因仍未定位；电源和 Full-Speed 桥接行为继续保留未验证边界。

## 最终交付与下一步

实验结束后刷回 `0.3.1-cdda-probe` 默认关闭配置，保留实验开启的固件/源码/配置及日志快照。日常启动只查询和读取目录，不自动进行音频实验。默认关闭后的独立采集和产物校验值见下方。

下一步扩大持续读取时长、随机/跨轨寻道和参考覆盖，再接入 PCM 环形缓冲和 I²S。USB DMA、缓冲欠载、首读/寻道最长延迟不能由本次短突发替代。输出声音阶段需要 I²S 立体声 DAC（如 PCM5102A 模块）、有源音箱或立体声耳放/功放；DAC 线路输出不能直接驱动无源音箱。
