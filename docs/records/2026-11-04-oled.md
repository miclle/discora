# 2026-11-04：SH1106 OLED 曲目与播放状态软件验证

## 范围与证据

源码版本 `0.10.0-oled`。按 GPIO10 SDA／GPIO11 SCL 接线实现 SH1106 128×64 I²C 显示，播放器模式默认启用，默认 7-bit 地址 0x3c，可改为 0x3d。状态为 **implemented**；本次未打开设备串口、未烧录、未测 OLED／电源／声音。

历史最后部署记录仍为 `0.9.1-track-buttons` 软件时钟播放器；本次不据此声称已重新核实板上版本。OLED 实物控制器、地址与上拉仍待确认。无新增光驱型号、桥接器 VID:PID 或测试光盘实测数据。

## 已完成的软件检查

- `python3 firmware/tests/run_host_tests.py`：11 组 C ASan／UBSan 检查通过，包含已有 50 万步播放器状态组合。
- 新 OLED 检查使用实际播放器核心和生产渲染／分页代码：启动无目录、TOC 非 1 起始轨号、换轨和边界拒绝、故障、失去介质清除轨号、全部状态文字、重新渲染清除旧像素、软件时钟与 I²S 底行区分。
- fake I²C 验证 8 页按列 2–129 写入、保留两侧未用列，并逐一注入 16 个页地址／数据事务失败，确认立即停止后续发送；初始化和开屏失败返回通过。该替身不证明真实总线、任务调度或资源清理成功。
- 用生产渲染器导出 STOPPED／BUFFERING／PLAYING／PAUSED／UNDERRUN／FAULT／NO MEDIA 七张画面，人工查看无文字裁切或重叠；这是软件像素检查，不是屏幕照片。
- ESP-IDF **v5.4**，Xtensa GCC **14.2.0**：默认查询、CD 软件时钟、CD I²S、测试音四配置均执行 `set-target esp32s3` 和 `build` 通过。生成配置确认仅两种播放器模式启用 OLED，地址为 0x3c。
- 同一 Xtensa 编译命令局部检查：I²S BCLK／LRCK／DATA 分别占用 GPIO10 或 GPIO11 的六种配置均按预期编译拒绝；关闭 OLED 的显示／播放器文件和地址 0x3d 的显示文件编译通过。局部检查不等于这些变体的完整链接或上板测试。
- 首次播放器构建发现刷新调用遗漏帧参数，补齐后四配置通过；主机侧纯渲染测试不能代替 ESP-IDF 集成构建。
