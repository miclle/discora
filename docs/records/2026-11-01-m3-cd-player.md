# 2026-11-01：真实 CD 源接入控制核心与软件时钟

源码 `0.6.0-cd-player`，ESP-IDF v5.4 (`67c1de1eeb`)，默认 / CD 软件时钟 / CD I²S 三种配置分别 set-target / build 通过；五组 ASan/UBSan 主机检查通过。I²S 配置仅构建，没有上板或接 DAC。设计见 [ADR-0008](../decisions/0008-cd-player-control.md)，命令和边界见 [使用说明](../cd-player.md)。

保持同一 ESP32-S3、COM `1a86:55d3` / `5CF9109063`、OTG 直连、充电宝辅助供电和 13 轨音乐 CD 不动。桥接器 `13fd:0840`、Full-Speed BOT `08/02/50`、UJ-898 / HC10、IN 0x81 / OUT 0x02、MPS 64、LUN 0、lead-out 252645。延续此前供电状态，不是冷启动验收。

## 控制实测

软件时钟配置，启动 stopped，目录发布后 reads=0。由采集程序通过目标 UART 显式发送命令；原始发送顺序和时间戳保存在 player-checks.json，没有让模式上电自动读取。

- play：从首轨 INDEX 01 预填并进入 playing；数据来自真实 READ CD。
- pause：两次独立状态采样（设备时间 9004 / 10584 ms）均为 paused、delivered=747936、queued=136416，消费量不变；play 后 delivered 增加到 804384。
- next → 轨 2、prev → 轨 1、track 13 → 轨 13，均进入 playing。换轨由 generation 2 → 3 → 4 → 5，队列和当前交付量清零。
- track 99 被拒绝，仍在轨 13 / generation 5 / playing，消费继续。
- stop 后两次采样均为 stopped、queued=0、reads=108，未继续接受新读取。随后快速 play→stop 仍保持 stopped。
- 实际出现两个已成功的旧代次 READ CD 返回：换轨前的 generation 2 / LBA 424，以及快速停止前的 generation 6 / LBA 223767。两者均被拒绝，最终 stale=2，未推进新代次队列或光标。这是实际在途结果丢弃证据，不是人工注入。

控制采集 19.485 秒，所有检查通过；一次枚举，零读取失败、零 USB 传输错误、零离线、欠载 0。源 EOF 和源错误后的停止本轮仅有离线测试覆盖，未人为拔盘或触发光驱错误。默认恢复采集 25.2 秒，目录有效、READ CD 数 0。

## 独立持续窗口

复用同一软件时钟应用及配置，只改变主机命令序列；没有重新编译或改变接线。上电 stopped，显式 play，首次 playing 后每约 10 秒采样，共六个间隔；最后显式 stop。

按设备日志时间计，连续窗口 60.47 秒，消费增量 10666908 字节，平均 176400 bytes/s（1×）。所有采样均为 playing、generation 2、underruns=0；窗口两端 delivered 为 33516 / 10700424。整个采集 66.667 秒，停止后 queued=0，无读取失败、USB 错误或离线。

本轮持续窗口没有单独累计 PCM SHA-256，不替代以前 600 秒顺序窗口与电脑的完整内容对照；这里证明新任务/控制链路的持续计时消费和短时稳定性。队列字节顺序、尾部短批及旧代次隔离另由同一核心的合成输入测试覆盖。没有保存商业 CD PCM，也没有输出真实声音。

## 部署与证据

每次部署先实时校验默认 0.4.3 应用，复用并核对 sense-control 的 0x0–0x110000 备份，仅写应用 0x10000；写入校验成功。这不是新读取的备份或完整 16 MB Flash。每轮 finally 恢复默认关闭实验的 0.4.3。

最终 25.005 秒采集取得有效目录、5 次 TUR 成功、READ CD 数 0、无离线，串口已释放。源码当前 0.6.0，不等于最终上板的 0.4.3。
