# GPIO7 轻触按键退盘：实现与离线验证

日期：2026-11-01。源码 `0.9.0-button-eject`，ESP-IDF v5.4，target esp32s3。本轮没有打开串口、烧录或发起真实退盘；最后已有部署记录仍为 0.4.3 查询固件，未重新读取设备版本。工作区原有外壳目录及 README 外壳链接保留，没有提交或推送。

## 实现与可测假设

目标是在现有 ESP32-S3 N16R8 + UJ-898 / HC10 + `13fd:0840` 桥接链路中，用 GPIO7 到 GND 的常开轻触按键触发显式退盘。GPIO7 选取依据供应商排针摘录 J1-7，不代表当前实物逐网核对。

30 ms 双向消抖、上电先释放、长按单次；独立输入任务只投递有界请求。唯一 USB client 在当前操作完成后清除目录/播放状态，等待输出任务确认关闭，依次发送 ALLOW MEDIUM REMOVAL 与 START STOP UNIT。无盘/数据盘不依赖音频目录；设备未识别、失联或故障不允许发起。失败无自动重放，断连不保留请求给下一设备。协议与行为见 [ADR-0010](../decisions/0010-gpio-eject-button.md)。

## 软件检查

`python3 firmware/tests/run_host_tests.py`：9 组 C 检查通过，启用 ASan/UBSan。

- 新增消抖、上电按住、释放抖动、长按、单槽合并、断连清队列、不可用/忙时丢弃请求测试，使用生产 `eject_button_core.c`。
- 三种受支持 subclass 的 ALLOW/eject 完整 31 字节 CBW 与预期逐字节一致；0 数据长度、6/12 字节 CDB、固定 Prevent / LoEj / Start 位、非法数据长度/子类/空指针检查通过。
- 既有 USB 超时/所有权、播放器旧代次/连续模式/介质失效、I²S fake driver 和 50 万步播放器组合回归通过。
- 这些测试不是实际 GPIO 波形、任务调度时序、USB 机械命令返回或光盘退出证据；按键→输出关闭→USB 的完整硬件链路尚未实测。
