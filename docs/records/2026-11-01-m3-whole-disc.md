# 整张 CD 的播放器软件时钟验证

状态：单张 CD 的 13 轨软件时钟验证通过（bench-tested）；不是整盘 I²S / DAC 输出验收。

2026-11-01，实测镜像 0.7.2-i2s-report，源码快照对应 `50dad08` 固件。ESP-IDF v5.4 (`67c1de1eeb`)；ESP32-S3 N16R8、UJ-898 HC10、桥接 `13fd:0840` Full-Speed BOT，COM `1a86:55d3` / `5CF9109063`。OTG 直连与辅助供电不变，未连接 PCM5102。

本次启动实际 TOC 共 13 条音频轨、首轨从 LBA 0 开始、lead-out 252645。目标总量 594221040 字节，音频时长 3368.6 秒（56 分 8.6 秒），另有预填/EOF 观察及轨间命令耗时。每轨明确选择并以软件时钟消费至 EOF，再验证摘要/尾块/队列为空和读取停止；通过后进入下一轨，不循环，不在错误后自动重试，不宣称无缝音频播放。

脚本必须读取本次会话的完整 TOC，不依赖旧清单；当前整盘总截止 90 分钟、轨长上限 480 秒。每轨保存 JSON 检查点，任何失败保留已完成轨及原始日志，finally 恢复查询固件。本地部署脚本与仓库 bench 分开：后者不烧录。

原始证据 `.local/bench/2026-11-01-m3-whole-disc/` 保存固件/配置/源码、工具快照、`scenario/serial.log`、逐轨 `scenario/report.json`、部署前校验及恢复记录。只写应用 `0x10000`，复用已核对的有限范围备份；不是冷启动验收。仅保存计数和摘要，不保存音乐 PCM。

准备阶段十项 Python 离线检查通过，包括本会话 TOC 完整性、音频轨及连续边界拒绝规则。工具不更改固件单轨停止语义。

## 实测结果

- 场景用时 3416.922 秒（约 56 分 57 秒），其中音频 3368.6 秒，其余为初始就绪、预填、轨间命令和 EOF 停止观察。
- 13 / 13 轨完成，源端与消费端各 594221040 字节，逐轨 SHA-256 全部相同；累计 31586 次 READ CD，等于各轨按最多 8 扇区拆分的次数之和。
- 每轨 EOF 后 state=stopped、queued=0、pending=0，连续观察期间不追加读取；尾块长度与实际轨长一致。末轨停在排他末地址 252645。
- 欠载 0、旧代次丢弃 0、报告丢弃 0；原始日志没有读取失败、传输超时、device closed、panic 或 brownout 记录。单轮成功不覆盖此前间歇性寻道失败，也未触发实际恢复分支。
- 所有轨末 heap_free=161100、heap_min=160960、output_stack_min=3872 字节；此有限窗口未见轨间内存持续下降，不能单独证明所有路径没有泄漏。

## 恢复与证据

完整场景结束后自动刷回并校验 0.4.3-underrun-bench；25.069 秒窗口取得有效 13 轨 TOC、5 次 TUR 成功、READ CD 发送数 0，无离线或传输错误。串口关闭后才开始后续 0.7.3 USB 等待正常路径回归；该短回归另见 [等待编排记录](2026-11-01-m2-wait-flow.md)。

`checks.json` 独立复核逐轨长度、尾块、摘要、读取次数及恢复日志，`sha256-manifest.json` 关联原始串口记录、报告、镜像、配置和源码快照。数据只覆盖该张 CD 的 TOC 轨道区间，不包含 pregap/隐藏轨、其它盘、冷启动、物理断连或真实音频输出。固件仍为单轨 EOF 停止；下一轨由电脑 bench 明确选择，不宣称连续无缝播放。
