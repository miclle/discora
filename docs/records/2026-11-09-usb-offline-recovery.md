## 修复一：停止／换曲后不再恢复旧读取

原有 `recovery_healthy()` 只检查 USB 连接、故障、transfer 所有权及 TOC。若长时间读取或 REQUEST SENSE 期间用户停止或换曲，播放器代次已改变，但设备仍健康，恢复流程仍可能等待、TUR 并再次 READ CD 旧位置。最终 PCM 有代次保护，不会混入新曲；问题是无用的再次读取、延迟新曲和消耗一次恢复预算。

当前同步 `read_audio()` 调用期间记录对应播放器请求，恢复健康检查同时查询加锁的请求身份。新 `cd_player_read_current()` 与完成接收共用 pending／generation／serial 条件，使“可以继续恢复”和“可以接收结果”的身份判定一致。

- 恢复开始前已失效：拒绝进入，不消耗预算。
- 恢复等待期间或 TUR 后观察到失效：不再启动后续恢复命令；已经消耗的预算不退款。
- 暂停保留原在途逻辑读取；独立 CD-DA bench 没有播放器请求，不受此检查影响。
- 检查之后已经提交的 USB 命令仍正常等待回调，结果按代次隔离；不承诺强制取消、瞬时停止光驱或硬件级原子取消。

## 修复二：超时清理期间的断连正确分类

原 `transfer_wait()` 仅在开始取消／清理前保存 disconnected。若 100 ms 截止先触发、140 ms 才观察到设备断开、160 ms 归还 transfer，原函数仍返回 TIMEOUT，掩盖随后观察到的断连。

清理结束时再次检查 gone，设备失联优先返回 DISCONNECTED。无回调的 transfer 仍保持 owned，清理期限不延长，也不伪造完成或解除隔离。原 timeout 事件日志仍保留，最终结果补充“随后确实断连”的事实。
