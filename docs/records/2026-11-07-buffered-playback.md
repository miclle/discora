# 2026-11-07：2 MiB 缓冲、自动恢复与连续播放

## 范围与设备

源代码基线 `332b384`，本次工作版本 `0.11.0-buffered`。ESP-IDF v5.4，ESP32-S3 rev 0.2、16 MiB Flash / 8 MiB Octal PSRAM；COM 尾号 8636，芯片 MAC `b8:1f:3f:d6:08:88`。光驱为 MATSHITA DVD-R UJ-898 / HC10，桥接 `13fd:0840`、Full-Speed；同一张 13 音轨音乐 CD，lead-out LBA 252645。

GPIO15→BCK、GPIO16→LRCK、GPIO7→DIN，GPIO4 留空；PCM5102A 独立 5V、SCK 接 GND、H3 高、主控共地，模拟 L/R/AGND 直连 TPA3118D2 输入。保持 44.1 kHz / PCM16 原始立体声、16-bit slot、双声道各 25% 数字幅度，按键和 OLED 关闭。

本地实验目录 `.local/bench/8636-buffered-20261107/`（忽略，不提交二进制、备份、PCM）。只写 factory 应用 `0x10000`，1 MiB 分区；独立校验应用与原始前 64 KiB 启动/配置区。原应用及配置备份保留。

## 变更前失败窗口

旧连续候选使用 64 扇区队列，首轮播放约 2113.72 秒，轨 1～8 完成，轨 9 约 100.48 秒处欠载：`queued=0 pending=1 reads=19805 underruns=1 continuous=0`。当轮未见 USB 掉线、I²S 写入错误；16 次事件队列溢出来自前 8 轨 EOF 收尾。约 1.76 秒后在途读取成功返回，但控制器已经停止并改变代次，作为 stale 被拒收。旧固件没有请求开始时间，不能将 1.76 秒当作完整请求耗时。

从轨 9 重启后再次欠载：`pcm_submitted=47377512`、`queued=1176 pending=1 reads=2518 underruns=1`，I²S 写入错误和事件溢出为 0；输出已关闭，外部控制器停止。该窗口保存在原连续实验目录的 `resume-1794033916484557000/`。两次都不是整盘自然结束。

## 实现与离线验证

- PSRAM 软件 PCM 队列 2097152 字节（约 11.89 秒），预填 529200 字节（3 秒）。默认无 PSRAM 配置保留内部 64 扇区。分配失败显式停止初始化。
- 欠载后输出 owner 先关闭 I²S，再保留 generation、源游标、在途请求及队列进行预填，补足后恢复；明确的控制操作和真实错误阻止恢复。
- 记录已完成 read_audio 的端到端耗时、LBA、累计最大/平均值、≥100/500/1000 ms 次数及失败/拒收。未返回请求不计入，不逐次打印时间。
- ESP-IDF PSRAM 原子包装器使原编译期“始终 lock-free”断言不适用；适配器强制内部 RAM，内部地址仍由 IDF 分派到硬件原子操作。未移动 ISR 计数器到 PSRAM。
- 主机 ASan/UBSan 全套通过，包括新增恢复字节顺序、前后返回竞态、重复欠载、暂停/停止/换轨/失联/失败、短 EOF、耗时边界和双声道增益。既有 500000 步独立 FIFO 检查与 15 项 bench 工具检查通过。
- ESP-IDF v5.4 的默认、内部 RAM I²S、PSRAM I²S、PSRAM 恢复注入配置均完成 `set-target esp32s3` 和 build；CI 增加 PSRAM profile，本次尚未推送或取得远端 CI。

## 上板窗口

恢复候选首次启动识别 8 MiB / 80 MHz PSRAM，`SPI SRAM memory test OK`；日志 `PCM buffer bytes=2097152 prefill=529200 memory=PSRAM auto_recover=1`。

**第一轮未通过，保留失败记录**：LBA 0 首次 READ CD 在 1.405706 秒返回失败，transport `ESP_ERR_INVALID_STATE`，随后 `device closed` 和重枚举。I²S 尚未启动、软件欠载 0、注入尚未执行。播放器进入 fault，没有擅自恢复播放。这是实际 USB 失联，不能称作自动重缓冲失败或成功，也未定位电气根因。日志位于 `recovery-attempt1/`。

### 受控恢复通过

第二轮首次受控供数暂停通过，但欠载和重缓冲连续投递两份完整状态造成 4 条诊断报告丢弃，未出现音频写入错误。删除重复状态快照后重建并重新上板，最终恢复候选再次通过；正常候选使用相同修正，之后又为跨曲报告突发扩容队列（见下文）。

最终恢复候选 SHA-256：`9ac85d982236a628f5a75c0ebb6d8ac14d675cea54d2139553842ba45cb2b524`。`test delay` 明确标记为生产者暂停 15000 ms，只暂停新读取，不伪造 USB 成功或 sense。

| 观测 | 结果 |

| 实际欠载 | 恰好 1 次，队列剩 1176 字节不足下一输出块；输出关闭后进入自动 prefill |

控制器在注入后没有发送 play 或 play-disc，恢复由 MCU 自行完成。软件 FIFO 字节连续性由离线测试覆盖；此次 I²S 关闭／重开不承诺模拟输出无缝。

### 正常连续播放

首个正常候选（SHA-256 `b597c67ac6cdf4570eb20158205cd17ddf05ad806f81a9f5fcb206d01f1780af`）不含故障注入，连续运行约 349 秒，从轨 1 自动进入轨 2。用户确认左右音乐都正常。软件欠载、读取失败、拒收、I²S 写入错误及 USB 失联均为 0；首次 LBA 0 预填读取最大 3664614 μs，此后已完成读取均低于 100 ms。

轨 1 EOF 收尾产生 2 次 I²S 完成事件队列溢出（最后 PCM 写入时为 0，关闭前为 2），与历史 EOF 排空行为一致，不能据此宣称硬件没有静音间隙。另外，EOF trace + 扩展状态 + sequence 同时到达使原 8 项报告队列丢 1 条报告；这属于诊断丢报，不是 PCM 数据缺失。随后将报告队列扩为 16 项（仍为非阻塞有界队列），保留计数，正常控制器也允许用 stopped + eof=1 确认自然盘尾，而不只依赖一条日志。

为更新报告队列进行一次维护停止并确认 I²S 关闭，保留 `continuous-v1/` 全部日志。最终正常应用再次仅写应用分区，启动/配置区与应用独立校验通过；自动恢复状态机、音频与 USB 读取逻辑未再改变。最终正常应用 SHA-256：`bb4515852fdedf44ca9f05ff0ed1e7653e86ac18f3480136d2f786b1bb94e471`，没有故障注入。恢复状态机的上板通过对应前述恢复候选；最终差异是诊断报告队列从 8 扩为 16，未重新改变音频逻辑。

观察结束时继续播放轨 2，未发送 stop；日志在 `continuous/`，快照为 `acceptance-snapshot.json`。此轮确认初始跨曲和短时连续输出，不宣称完整 13 轨或原轨 9 延迟窗口已经通过。

本地 `active-controller.json` 指向当前连续控制器目录。控制器每约 5 秒查询状态；允许固件自动重缓冲，遇真实源/输出 fault 停止并保留日志。仅在确认自然盘尾后从轨 1 再播，以执行用户“直到我说停”的持续播放要求。创建其 `stop` 文件可请求控制器发送 stop、确认 I²S 关闭并释放串口；不能在它持有串口时另开串口工具。


## 限制

不保证采样连续、轨间无缝或无静音恢复；关闭 I²S 可丢弃约 40 ms 已提交 DMA。读取摘要与状态计数不等于模拟声音验收；PSRAM 缓冲不能修复 USB 失联、无限等待或持续不足的输入速率。启动区保留原配置，其 Flash 容量提示不能作为音频异常归因。

## 后续持续观察至停止

按用户要求继续观察，最终约 55 分钟时在第 13 轨发生 USB 失联，未自然到盘尾。前 12 轨完整结束，软件欠载和 I²S 写入错误仍为 0；停止前缓冲充足，问题归于 USB 设备失联路径，具体根因未定。当前播放已停止，I²S 和串口均释放。完整统计、时间线及证据边界见[持续播放日志分析](2026-11-07-buffered-continuous-log-review.md)。上文 284.2 秒通过是早期窗口，不能作为整盘成功结论。
