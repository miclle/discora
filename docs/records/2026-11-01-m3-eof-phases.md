# I²S EOF 收尾阶段定位

2026-11-01，保持 COM / OTG 直连 / 光驱辅助供电不变，不连接 DAC。ESP32-S3 N16R8、UJ-898 HC10、桥接 `13fd:0840` Full-Speed BOT；目标 COM `1a86:55d3` / `5CF9109063`，其它串口不操作。ESP-IDF v5.4 (`67c1de1eeb`)；同一 13 轨音乐 CD，首轨 LBA `[0,19373)`、45565296 字节。

## 假设与方法

0.7.3 的状态报告已经异步化，但 EOF 摘要仍在输出任务持有队列锁时同步打印，之后才开始 50 ms 排空。需要区分供数、摘要处理、排空和关闭期间的驱动完成事件溢出。

0.7.4-eof-trace 只增加内存快照：最后一次 PCM 写入返回、摘要前、摘要后、排空起点、关闭前和关闭后。快照包含单调微秒、DMA 完成块及事件队列溢出累计值；仅在关闭后异步输出三条记录，采样窗口内不新增 UART 日志。计数完整保留，未改变 50 ms 策略。

## 同步摘要基线

| 摘要前 | 267938361 | 26199 | 0 |
| 摘要后 | 267956760 | 26200 | 0 |
| 排空起点 | 267956776 | 26200 | 0 |
| 关闭前 | 268006908 | 26205 | 3 |
| 关闭后 | 268007308 | 26205 | 3 |

摘要处理窗口 18.399 ms，排空等待 50.132 ms；全部 3 次溢出发生在排空期间，供数阶段为 0。首轨源/消费摘要一致，尾块 1176 字节，写入错误、坏 DMA 长度为 0，停止后计数稳定。

核对本地 v5.4 `esp_driver_i2s/i2s_common.c`：完成事件队列为 `desc_num - 1`，本配置容量 3；队列满时 ISR 移除旧事件、调用 `on_send_q_ovf` 并投递新事件。EOF 后应用不再调用 write 消费这些事件，而外设仍运行。这解释了本窗口的事件积压，不构成真实 PCM 丢失或完整输出的测量。

## 异步摘要对照

0.7.5-eof-report 将两条 EOF 摘要改用已有有界报告队列；保留同一首轨、控制前序和 50 ms 排空，不通过清零事件计数或缩短排空掩盖现象。同轨对照通过：源/消费各 45565296 字节、摘要相同，尾块 1176，写入错误和坏 DMA 长度为 0。

| 摘要前 | 267968367 | 26224 | 0 |

摘要窗口降至 0.713 ms；排空截止仍为 50 ms，任务实际在 57.811 ms 后执行关闭。供数和摘要阶段均为 0，排空阶段产生 2 次事件溢出。此结果与事件容量 3、最后提交后继续完成 5 块一致；不把事件溢出计数清零，也不称为有效 PCM 丢失两块。引脚波形和物理尾音仍未测。

默认查询、软件时钟、I²S 观察配置分别 set-target / build 通过；8 组 C 离线检查通过。两轮结束后均恢复并校验 0.4.3 查询固件，采集有效 TOC，READ CD 关闭；串口已释放。阶段输出快照保留原始累计值，整盘工具将单独拒绝供数阶段的溢出，并保存收尾差值。

证据分别保存于 `.local/bench/2026-11-01-m3-eof-trace/` 和 `.local/bench/2026-11-01-m3-eof-report/`，包含源码/配置/镜像、原始日志、阶段快照、SHA-256 清单和默认固件恢复记录。只写应用 `0x10000`，复用核对过的有限范围备份；不是冷启动验收。
