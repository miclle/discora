# 轨尾恢复与 I²S 适配器离线回归

2026-11-01，源码 0.6.4-player-tail / ESP-IDF v5.4 (`67c1de1eeb`)。本阶段不烧录、不打开 COM、不改接线；设备继续运行上一阶段恢复的 0.4.3 默认查询模式。PCM5102 未到，I²S 与模拟声道均未实测。

## 发现与修复

新回归用例先让源到达 EOF，再消费至最后 1176 字节，pause 后 play。修复前共享核心返回 prefill，因为剩余数据不足正常门槛，而 EOF 又阻止新增读取；测试在 `state == AUDIO_PLAYING` 断言失败。修复为已知 EOF 的非空队列直接恢复消费，短尾块消费完正常 stopped，不额外读取。

相同情况重新打开 I²S 时，原适配器要求预装恰好 7056 字节，会拒绝短尾块。现在允许非零、4 字节帧对齐且不超过 7056 的预装；实际 PCM 后补零到 DMA 容量，检查每次 preload 返回长度。只在短 EOF 启动路径补齐，不用于掩盖普通欠载，不计入 CD 数据摘要。用本地 IDF v5.4 的 `i2s_channel_preload_data` 实现核对多次 preload 从上一次加载位置继续。

EOF 50 ms 截止移入适配器，重复 EOF 不延长，停止/关闭清除截止。它仍是软件等待策略，不是硬件排空测量。暂停可能丢弃已经提交的约 40 ms DMA 音频，未实现无缝暂停。

## 验证

六组 ASan/UBSan 主机检查包括生产 `audio_i2s.c` + 测试专用 IDF 头与函数替身，没有重写适配器控制流程。覆盖引脚拒绝、创建失败、初始化/查询失败清理、删除失败保留句柄、短 preload、enable 失败、部分 write/错误、disable/delete 失败后重试、暂停后重建、短尾块补零及 EOF 截止边界。另用上一提交的播放器核心运行新用例复现失败，再以当前核心通过。

本地 `.local/bench/2026-11-01-m3-player-tail/` 保存 `before-fix-test.log`、`host-tests.log`、四配置 set-target/build 日志、配置与源码快照/摘要。默认查询、CD 软件时钟、CD I²S、独立测试音都独立构建；没有把编译或替身结果记为硬件通过。
