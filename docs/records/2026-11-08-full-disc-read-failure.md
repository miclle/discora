# 2026-11-08：整盘播放在第 13 轨读取失败

## 结果

用户要求播放整张 CD，结束或停止后分析稳定性日志。本轮于 **10:28:15（Asia/Shanghai）** 开始采集，只发送一次 `play-disc`。前 **12 轨完整提交并正常跨曲**，第 13 轨输出约 **2 分 13 秒**对应的 PCM 后，LBA **233783** 的 READ CD 失败，播放器进入 fault，未到盘尾。**本轮整盘稳定性未通过。**

首次 running 状态至首次 fault 状态日志相隔 **3125.480 秒（约 52 分 5 秒）**；它是状态采样窗口，不是独立声学计时。控制器总采集时间 **3138.310 秒**，含启动、停止和确认。第 13 轨提交量为 23383584 字节，按 176400 bytes/s 折算 132.560 秒；故障 LBA 是源读取位置，不等于扬声器播放位置。

故障后控制器发送一次 `stop`，确认 `stopped`、`continuous=0`、`queued=0`、`pending=0`、`tx=closed`、`handle=0`，串口已释放。没有重播、烧录、修改固件或执行介质写入。

## 失败顺序

失败命令为第 13 轨、LBA 233783、8 扇区，请求 18816 字节。使用诊断事件自身的微秒字段排序；异步日志前缀不能替代事件时间。

| 事件时间（秒） | 观察 |
| --- | --- |
| 3120.703458 | READ CD 开始，tag=29854 |
| 3120.703676 | DATA 等待开始，CBW 已完成 |
| 3130.376079 | DATA 回调 `status=4`、actual=0；本机 IDF v5.4 中为 `USB_TRANSFER_STATUS_STALL`，不是 `NO_DEVICE` |
| 3130.394970 | 命令结束：有效 `CSW=1`、received=0、residue=18816；总耗时 9.691512 秒，DATA 9.672698 秒 |
| 3130.403074 | REQUEST SENSE 开始，tag=29855 |
| 3131.457358 | REQUEST SENSE 完成，CSW=0、18 字节、residue=0；命令耗时 1.054284 秒 |

REQUEST SENSE 返回 `key=0x03 ASC=0x02 ASCQ=0x00`。其中 ASC/ASCQ `02h/00h` 的标准说明是 **NO SEEK COMPLETE（寻道未完成）**，见 [T10 ASC/ASCQ 分配表](https://www.t10.org/lists/asc-num.txt)。这是一条实际设备返回，不能仅凭它断定光盘损坏、光头故障或供电异常。

源码的 DATA STALL 分支清除端点 halt 后继续读取 CSW；本轮随后取得有效失败 CSW 和成功的 sense，未走应用 BOT reset 路径。`control_us=449` 与这次端点处理相符，不能把它称为整机 USB 复位。日志随后明确 `no further read retry`，源结果被拒收，播放器清队列并关闭 I²S。故障后的两次 TEST UNIT READY 都成功，`media=1` 保留，但没有再次读取音频。

这是 **SCSI 读取失败触发停止**，与此前根端口 DISCONNECTION 的失败类型不同；没有证据将它们合并为同一根因。软件欠载为 0，不能把此次停止解释为缓冲先耗尽；fault 后的 `queued=0` 是清队列结果。没有独立的故障瞬间队列快照，不把最低采样值当作精确剩余量。

## 结论与后续方向

1. 本轮前 12 轨、12 次自动跨曲及约 52 分钟运行已有真实日志；整盘播放仍失败，不能标为 verified。
2. 本轮没有复现此前根端口断开，新增的是有效失败 CSW 与 `03/02/00`。主控串口身份也不同，不能据此宣布此前失联已修复。
3. 2 MiB 缓冲覆盖了多次秒级等待，最终停止来自真实源失败；增大缓冲或仅开启欠载自动恢复不会改变该失败返回。
4. 若继续定位，优先围绕同盘 LBA 233783 附近做有界只读对照，比较电脑与 MCU 的实际结果，再考虑另一张盘的对照以区分介质位置与设备路径。此为后续建议，本轮未执行重读、换盘、自动重试或固件修改。
