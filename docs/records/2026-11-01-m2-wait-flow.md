# USB 长等待、取消与迟到回调离线覆盖

2026-11-01，0.7.3-transfer-wait。将 `usb_probe.c` 原有等待/取消截止控制抽为 `transfer_wait.c`，真实 Host 和主机测试使用同一编排；生产适配仍调用原生 Host 事件服务、halt/flush。普通/READ CD/sense 截止不变，取消排空等待仍为 2000 ms，不增加命令重试或写盘行为。

## 不变式与用例

- 只有真正的完成回调解除 in_flight；超时本身绝不伪造归还。
- 期限内完成、等待期间设备离线、完成与离线同时到达分别检查结果。
- 超时后取消，随后返回的完成只归还所有权，不能把原超时转成成功。
- 取消排空期限结束仍被 Host 持有则保留所有权，禁止复用；迟到回调最终归还后才解除持有。
- EP0 没有可用取消 API，不调用 endpoint halt/flush；同样保留未归还所有权。
- 虚拟时间完整经历 30000 + 2000 ms，截止与隔离有界。
- 一个虚拟 5 秒待完成请求中，40 ms 执行 stop，60 ms 换轨；旧请求返回后拒绝旧数据，并且不清除新代次 pending。

这些测试直接调用共享等待代码和播放器核心，fake 仅提供事件/时间/所有权观察。它们没有真正拔设备或延迟 USB 中断，不证明物理断连、Host 驱动取消或真实光驱恢复已经验收。

阶段七组 ASan/UBSan 检查通过。源码/测试及结果保存在本地 `.local/bench/2026-11-01-m2-wait-flow/`；ESP-IDF v5.4 / esp32s3 的配置构建证据另保存在 `.local/bench/2026-11-01-build-matrix/`。整盘实验固定使用之前的 0.7.2 镜像，未在其中途更新设备。
