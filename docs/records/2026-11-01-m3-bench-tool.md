# 仓库播放器 bench 工具

2026-11-01，`firmware/tools/player_bench.py` 固化不依赖 DAC 的软件验证流程，配套 `firmware/tools/README.md`。

- `inspect` 仅枚举并核对明确的端口、USB VID/PID、序列号；匹配不唯一或路径不同即拒绝，不打开设备。
- `eof` 校验指定轨长、生产/消费 SHA-256、最后输出块、代次及停止后的读取计数。
- `stress` 限 1–20 轮（默认 10），覆盖 pause/play、next/prev、非法轨号、stop、在途返回的代次隔离；当前场景适用于这张 13 轨测试盘。
- `faults` 仅向已部署的注入 profile 发送显式 test 命令，观察欠载停住、fault 拒绝 play、stop/play 恢复和启动预算不退款。

工具不包含刷写命令，不自动复位；COM 打开可能由驱动/板卡产生复位，启动日志会记录，并在 stopped 状态最多等待目录 45 秒。整体截止 600 秒，命令 2 秒、进入 playing 40 秒；任何异常保存已完成动作与失败原因。失败后尽力停止已经明确识别的软件播放器、释放串口，不能保证断连设备接收到停止命令。

保存原始串口 bytes 与 JSON 报告，包括工具/日志 SHA-256、UTC 开始时间、已观察到的固件版本、命令确认时间、队列及资源状态。输出目录不得已存在，不保存 PCM。不在无固件版本日志时臆测版本，也不把主机确认时间当作 MCU 硬实时延迟。

## 验证与限制

九项 Python 离线检查通过，已接入现有 CI 工作流（本轮未推送，未触发远端运行）：完整身份和拒绝错误/歧义目标、ANSI/带数字字段解析、命令 acknowledgement 后才接收状态、错误 sink 拒绝、传输错误中止、无响应有界退出、EOF 短尾报告及长度/摘要不一致拒绝。不需要 pyserial 或设备即可执行这些检查。

压力与故障场景的早期工具快照已分别用于 [10 轮实测](2026-11-01-m3-player-stress.md) 和 [受控故障](2026-11-01-m3-player-faults.md)。最后整理增加摘要/版本元数据和更严格的 acknowledgement / 换轨代次 / EOF 校验，经离线回归；没有为此重复烧录或重复长时硬件实验。仓库 EOF 场景通过离线 fixture，实盘整轨来自此前本地脚本的[独立实测](2026-11-01-m3-player-eof.md)，不声称仓库最终工具版本已完整重跑该场景。

本阶段仅 `inspect` 核对现有 COM 身份，未打开串口。板上保持 0.4.3 查询模式，接线不动；源码 0.6.4，真实 I²S / DAC、冷启动和真实光驱故障恢复依然未验收。

本地 `.local/bench/2026-11-01-m3-bench-tool/` 保存离线结果、身份枚举、工具/测试快照与 SHA-256 清单。阶段交付均为本地提交，没有 push 或触发新的远端 CI。
