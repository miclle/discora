## 范围与结果

用户要求沿用当前有声配置，从第 1 轨到盘尾，保持供电和接线不变，掉线即停止、不自动重试。2026-11-07 19:29:01（Asia/Shanghai）开始记录；只发送一次 `play-disc`。目录成功识别，但第 1 轨 LBA 0 的首次 READ CD 在 DATA 阶段发生 USB 根端口断开，尚未完成预填或打开 I²S。**本轮没有进入音乐输出，整盘稳定性未通过。**

## 结论与边界

1. 这次故障发生在 USB 数据读取层，I²S 尚未打开；不是音频输出已运行后发生的软件欠载，也没有先行应用 BOT reset。扩大 PCM 缓冲不能覆盖尚未读到任何数据时的设备失联。
2. [此前相同应用的约 10 分钟有声窗口](2026-11-07-usb-read-clock-comparison.md)通过，本轮却在首次读取即失败。该组合仍存在间歇性连接问题，不能因短测通过标记为修复，也不能把失败限定为长时间播放或第 13 轨。
3. 当前诊断定位到 Host 观察到连接消失，仍不能区分供电瞬态、USB 信号／连接路径、桥接器／光驱内部复位或 Host 底层异常。没有 ERROR／OVERCURRENT 或 MCU 重启不等于排除这些原因。
4. 本轮按要求结束，不追加同配置重播，也不重复测量已确认的音频接线。若继续定位，应针对 USB 连接丢失补充能区分上述原因的新证据，而非以自动重试掩盖故障。

本次仅保存日志分析并更新工程状态，未修改固件。

### 新增结论与未决问题

- **缓冲策略覆盖了约 7 秒的慢读取，但没有解决 USB 失联。** 断开时仍有 11.82 秒 PCM，停止来自设备失联处理，不是数据耗尽。
- 本次连接在最后一条命令成功结束后才消失，且没有应用 BOT reset。这与上一轮在途读取失败有所不同，不能将所有失联都归因为 READ CD 超时、I²S 写入失败或完成事件队列溢出。
- 慢读取出现在断开前，值得保留为时序线索；但随后还有成功读取，当前证据不能证明慢读取导致了掉线。约 1.315 秒后重连与此前两次约 1.32 秒的间隔接近，也不能据此直接认定桥接器内部复位或供电问题。
- 问题仍定位在 USB 连接消失这一层；供电瞬态、信号／连接路径、设备内部行为与 Host 底层原因尚未区分。当前音频线路不需要重复检查；本轮没有再发起任何播放或硬件对照。
