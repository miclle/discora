# ADR-0009：显式启动、有限结束的连续播放

- 状态：Accepted；实现 0.8.0，实测范围见对应记录

## 命令与边界

`play-disc` 从当前所选音轨的起点重新开始，依目录顺序播放到最后一条受支持音频轨；不绕回盘头、不改变默认固件配置、不在启动/目录发布/重连时自动播放。尚未手动选轨时，当前轨是第一条受支持音频轨。只跳过既有规则不支持的数据轨、四声道轨或过短轨，不增加写盘、机械控制或任意 CDB 入口。

`pause` 保留连续模式，`play` 恢复；在 EOF 排空期间也允许暂停，恢复后先完成原轨 EOF 检查，再进入下一轨。`stop` 和成功的 `track N` / `next` / `prev` 退出连续模式；非法/边界命令不改变模式。欠载、源失败、输出错误、介质失效立即取消连续模式，不自动重试或重新开始。单轨 `play` 在 EOF 后仍重新播放当前轨。

## 所有权与切换顺序

核心只保存连续模式和选择下一轨，不调用驱动。输出 owner 在上一轨软件队列耗尽、当前请求结束、逻辑 EOF 停止、I²S 排空截止结束且通道成功删除后，才调用核心 advance。开启摘要诊断时，还要求同代次 EOF 已完成且摘要/长度匹配；失败则进入 fault 并取消序列。

换轨改变 generation、清空队列、重置源光标，再由原有唯一 USB client 读取下一轨。旧 USB 返回仍按原代次规则拒收。下一轨重新预填和打开 I²S，存在轨间间隔，不宣称无缝或采样连续输出。默认 50 ms 排空仍只是软件策略。

末轨保留 EOF 与交付计数，continuous=0，不再读取；日志分别输出 `sequence advance` 和 `sequence complete`。`status` 增加 continuous 字段，它不是 USB 请求已取消的证据。

## 验证

共享核心离线检查覆盖 EOF 推进、跳过不支持轨道、盘尾不循环、暂停/恢复（含 EOF 边界）、手动取消、旧代次隔离、故障/欠载/失联取消与重连保持 stopped。普通/I²S 配置分别构建。

实机 bench 使用 `sequence`：选择起始轨并停止后，仅发送一次 `play-disc`，至完成检查前只发送 status；核对固件 advance 顺序、各轨摘要、关闭快照和最终 complete。实测结果见 [连续播放记录](../records/2026-11-01-m3-autoplay.md)。不以电脑脚本发送 next/track 的逐轨模式替代自主切换证据。
