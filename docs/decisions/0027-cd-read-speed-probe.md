# ADR-0027：可选 CD 读取限速实验

日期：2026-11-09。状态：implemented；实机证据与当前部署见[实验记录](../records/2026-11-09-read-speed-probe.md)。

## 背景

用户报告播放时光驱持续高速运转、机械噪声明显。现有播放器每次读取 1–8 扇区，PCM 队列有空间即继续供数；2 MiB PSRAM 约容纳 11.89 秒音频，用于抗读取延迟，没有主轴限速或缓存高低水位策略。听感和 USB 传输速率都不能直接证明实际主轴转速。

## 决策

- 增加默认关闭的 `DISCORA_CD_READ_SPEED_TEST`，仅在播放器模式提供 4×、2× 两个候选，分别请求 708、354 kB/s。使用 MMC `SET CD SPEED`（0xBB），12 字节 CDB、零数据阶段、LUN 0；写速度字段为零，不开放写盘命令、任意 CDB 或 Data-Out。
- 在 USB client 唯一命令线程内，完整 TOC 校验及可选 CD-Text 查询之后、发布可播放目录之前设置速度。每次有效目录发布前尝试一次，不在每批读取、每次换轨或暂停恢复时重复发命令。新介质就绪周期或重新连接、重新取得 TOC 后再申请；不假设主控复位会清除光驱内部速度状态。
- 仅 `05/20/00`（不支持命令）和 `05/24/00`（无效 CDB 字段）允许记录不支持后沿用光驱策略。NOT READY、UNIT ATTENTION、其它真实失败或无有效 sense 均不发布本次 TOC；传输异常仍沿用现有故障与恢复边界，不伪装成可忽略的限速失败。
- 保持缓存容量、3 秒预填、8 扇区读取、I²S 采样率、增益、超时及寻道恢复预算不变。先独立比较默认／4×／2×，不同时引入水位节流或播放中停转。
- 接受命令只记为 accepted，不标成已测主轴速度或降噪通过。最终默认仍关闭，直到具体硬件与介质的验证足够支持修改。

速度字段单位与取整参考 [Linux 光驱驱动 `sr_select_speed`](https://github.com/torvalds/linux/blob/master/drivers/scsi/sr_ioctl.c)，按 N×177 kB/s 编码；仅参考接口行为，没有引入第三方源码。该标准命令不证明 UJ-898／HC10 或桥接器一定执行指定速度。

## 验证

主机测试覆盖三种受支持 subclass 的完整 CBW 字节、2×／4×、非法速度拒绝、零数据阶段及写速度字段；直接提取生产 TOC／限速函数检查成功、不支持回退、坏 TOC、传输失败、命令或 sense 期间断连、介质变化与读取错误。默认查询、4×、2× profile 分别执行 ESP-IDF v5.4 的 `set-target esp32s3` 和 `build`。

实机按相同曲目和控制顺序比较，记录首曲／中间曲／末曲、暂停恢复、缓存最低值、读取最大耗时、失败、欠载与 I²S 写入错误。短窗口不替代整盘稳定性、实际转速测量或声学验收。
